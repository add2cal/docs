# Create a Calendar Subscription

A calendar subscription lets people follow a calendar over time. Their calendar provider checks the feed for updates. Use it for an ongoing schedule, rather than asking people to save every event separately.

## Choose the calendar source

Open or create an event group and find **Calendar Subscription**.

| Choice | What it does |
| :--- | :--- |
| **No** | Keeps a normal group of individual events. |
| **External** | Connects to a calendar feed managed outside Add to Calendar PRO. |
| **Using the group's events** | Builds one subscription calendar from the events inside the group. |

## Use events managed in PRO

1. Create a group with a name your audience will recognize.
2. Choose **Using the group's events**.
3. Choose a style and any landing page or CTA template you need.
4. Save and publish the group, then create or add compatible events inside it.
5. Publish the events and test the group's subscription link from its sharing summary.

This subscription type also enables the public event overview. You can offer a subscription button and an [event list](/application-manual/event-list) for the same group.

The app only permits compatible events: they must not use RSVP, dynamic dates, or explicit date status, organizer, or attendee fields. If the option is unavailable for an existing group, inspect its events for those settings. A new compatible group may be simpler.

## Use an external calendar

Choose **External** and enter the **URL of external Calendar**. Use the calendar's subscription/feed URL, not the address of a page that merely displays it. Ask the calendar owner for the feed if you are unsure.

Continue maintaining event details in that external calendar. Add to Calendar PRO provides the subscription entry point and its appearance.

An existing external subscription cannot be changed to another subscription type. Create a separate group when you need a different setup.

## Share and test

Use the group's **ProKey**, landing page, or email links. Subscribe with a calendar account you control and check that the expected events appear.

Changes do not appear instantly in every subscriber's calendar. The receiving calendar service decides when to refresh its subscription. Republishing repeatedly does not force that service to refresh.

Not every calendar supports subscriptions through the same flow. The app hides unsupported options; for example, Yahoo and Microsoft Teams are unavailable for subscriptions. On mobile, further provider limitations apply.

## Subscription or RSVP?

Choose separate [RSVP events](/application-manual/rsvp-forms) when you need attendee responses or a separate reservation for each session. A subscription is for following dates; subscribing is not an RSVP registration.

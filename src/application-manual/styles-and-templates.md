# Customize Buttons with Styles and Templates

Use a style to choose how your button or RSVP form looks and behaves. Use templates to add reusable registration rules, emails, landing page content, or follow-up messages.

[Open Styles in the app](https://app.add-to-calendar-pro.com/styles)

## Create a style {#styles}

1. Open **Styles** and create a new item, or create one while setting up an event.
2. Give it an **Internal Name**, such as “Webinars — English”.
3. Select the **Button Style**, **Calendar Options**, **Language**, and **Button Label**.
4. Check the preview, including light/dark mode and the Android/iOS simulations.
5. Save the style and select it in the event's **Style** field. Publish the event when its configuration is ready.

A style's internal name helps your team find it; the button label is the text visitors see. Changing the interface language of the app does not change the language selected in your event's style.

## Choose behavior that fits your page

| Setting | Use it to |
| :--- | :--- |
| **Render as list** | Show the calendar choices as a list instead of one opening button. |
| **Render RSVP inline** | Place the form directly on the page rather than opening it in a modal. |
| **Trigger / List Style** | Choose how the calendar choices open and where they appear. |
| **Past Date Handling** | Leave, disable, or hide the button after the event. |
| **Proxy** | Route calendar clicks through the hosted flow; needed for save-click analytics outside the landing page. |
| **Force Overlay** | Help when website elements cover the calendar choices. |

The **Date** button style is not compatible with RSVP. Some calendar options also vary by event type or device, even when selected in the style.

## Preview before changing a shared style

Use **Simulate RSVP** to preview a form, and check both light and dark colors. Keep labels readable and do not hide so much text that visitors cannot understand the button.

For a one-off variation, create a separate style instead of changing the one shared by other events. Check **Usage** in the additional-actions menu before saving. Changes to linked published events may take **3–10 minutes** to appear; events with draft changes need publishing.

**Custom Labels**, **Custom Style Light**, **Custom Style Dark**, and **Custom CSS** are for more detailed adjustments. Ask your website team for help with CSS; begin with the visual controls when possible.
